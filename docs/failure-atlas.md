# Failure Atlas — symptoms, discriminators, and dead ends

Search this page before opening a new hypothesis. These are normalized failure
families distilled across projects; each has a stable ID suitable for logs,
issues and project failure registries.

Failure IDs always use the global `FAIL-` namespace, such as
`FAIL-HAND-002`. Pattern IDs deliberately retain their shorter established
form, such as `HAND-002`; never omit `FAIL-` when citing an atlas record. Logs
created before the 2026-08-26 namespace migration may contain an unqualified
legacy failure ID and should name this atlas when interpreted.

## How to add a failure

Add a new `FAIL-DOMAIN-NNN` row only when it has:

1. an observable symptom;
2. a discriminator that separates it from neighbors;
3. a cause supported by evidence;
4. a route to a full recipe or chapter.

Project-specific addresses, hashes and dates belong in that project’s
`FAILURE_REGISTRY.md`. This atlas stores the transferable family. If a
premise was decisively falsified, record it even if no fix exists—the negative
result is what prevents the next developer from paying again.
